# РозкладкаВ

Мобільний застосунок (Android) для розрахунку норм протипожежного оснащення
та обліку фактичної наявності вогнегасників: скільки вогнегасної речовини,
вогнегасників і пожежних щитів має бути в будівлях та на території, виходячи
з площ приміщень — і чого саме бракує в реальному інвентарі.

**Логіка розрахунку норми** (див. `lib/services/calculation_service.dart`):
- Звичайні приміщення: 1 л вогнегасної речовини на кожні 10 м² (по кожному
  поверху сумарно, за вирахуванням площі кабінетів з комп'ютерною технікою).
- Кабінети з комп'ютерною технікою: окремий вогнегасник по кожному кабінету —
  до 20 м² один клас, понад 20 м² більший клас.
- Територія (ТВУЗ): 1 пожежний щит на кожні 5000 м².

⚠️ Точні класи/маси вогнегасників у коді позначені `TODO` — зафіксовані зі
слів замовника, без звірки з конкретним пунктом наказу.

**Облік реальних вогнегасників:**
- Кожен вогнегасник у системі має ідентифікатор (порядковий номер,
  присвоюється автоматично), заводський номер, інвентарний номер (лише
  цифри, мінімум 4 — перші 4 це код субрахунку бухобліку), тип і модель.
- Чотири типи, кожен зі своєю базовою номенклатурою моделей (див.
  `lib/models/extinguisher_model_catalog.dart`):
  - **ВП** (порошковий) — ВП-1…ВП-12 (переносні), ВП-20…ВП-100 (пересувні), кг
  - **ВВК** (вуглекислотний) — ВВК-1.4…ВВК-7 (переносні), ВВК-10…ВВК-55
    (пересувні), кг
  - **ВВП** (водопінний) — ВВП-2…ВВП-9 (переносні), ВВП-25…ВВП-100
    (пересувні), л
  - **ВВ** (водний) — ВВ-5…ВВ-10 (переносні), ВВ-50…ВВ-100 (пересувні), л
  - Базові моделі — незмінні. Понад них можна додавати й видаляти власні
    моделі (Налаштування → Номенклатура вогнегасників); код моделі не може
    повторювати вже наявний у межах того самого типу.
- Кабінети з комп'ютерною технікою обслуговуються виключно вогнегасниками
  ВВК — фіксоване правило.
- Для звичайних приміщень дозволені типи налаштовуються (Налаштування →
  за замовчуванням лише ВП).
- Усе керування вогнегасниками (перегляд, додавання, редагування) — на
  екрані "Вогнегасники", доступному з головної сторінки і з кожного рівня
  ієрархії (управління/будівля/поверх/кабінет).
- Застосунок рахує **недостачу**: скільки ще потрібно долучити вогнегасників
  певного типу/моделі, порівнюючи норму з фактично зареєстрованими
  одиницями ("Статистика").

**Ієрархія:** Управління → Будівлі (→ поверхи → кабінети) і Території/ТВУЗ
(паралельно, під тим самим управлінням). Будівлі рахують вогнегасники,
території — пожежні щити.

**Видалення** будь-чого (управління, будівлі, поверху, кабінету, території,
вогнегасника, доданої моделі номенклатури) завжди питає підтвердження.

**Редагування** доступне для кожного об'єкта: управління, будівлі —
перейменування (олівець у списку); поверх, кабінет, територія, вогнегасник —
повноцінна форма редагування.

**Довідка на кожній сторінці** — іконка "?" в верхньому куті відкриває
короткий опис того, що на сторінці і що можна робити.

**Оновлення потягом униз** — на всіх списках (Управління, Будівлі/Поверхи/
Кабінети, Вогнегасники, Статистика) можна потягнути список вниз, щоб
перечитати дані з бази, без перезапуску застосунку.

**Статистика** (екран "Статистика" — доступний з головної, з екрана
управління, будівлі й поверху, кожен раз відфільтрований на свій рівень) —
воронка **об'єкт → наявно/потреба**: підсумковий рядок поточного рівня і
розбивка по наступному рівню вниз (усі управління → по управліннях → по
будівлях і територіях → по поверхах → по кабінетах). "Наявно/потреба"
показується одним дробом (напр. "14 / 19"), червоним коли недостатньо —
без ручного віднімання. Три окремі таблиці — вогнегасна речовина (звичайні
приміщення), вогнегасники ВВК (кабінети з ПК) і пожежні щити (території, з
рівня управління й вище) — показуються **завжди на кожному рівні**; якщо
для категорії на цьому рівні нема об'єктів, замість таблиці — пояснення
("дані відсутні в системі: ..."), а не тиша. Чекбокси над таблицями
вмикають/вимикають категорії — впливають на екран і на PDF-звіт (не на
CSV — той завжди повний, це резервна копія). Звідси ж — CSV та PDF.

**Пожежні щити територій** тепер теж обліковуються фактично: на сторінці
території поле "Наявно щитів" (редагується вручну) — недостача рахується
як потрібно мінус наявно, так само як для вогнегасників.

**Експорт/імпорт CSV** — повне дерево даних в один файл (управління →
будівлі → поверхи з площами → кабінети з площами й ознакою ПК →
вогнегасники, і окремо території з площею й наявною кількістю щитів), з
UTF-8 BOM (коректно відкривається і в Excel, і в WPS, і на Android). Імпорт
створює або оновлює управління/будівлі/поверхи/кабінети/території
автоматично за назвою — нічого не має існувати заздалегідь. Вогнегасники
дедуплікуються за інвентарним номером, тож повторний імпорт того самого
файлу не плодить дублікатів. Той самий файл — це водночас і резервна
копія/спосіб передати дані на інший пристрій.

**Звіт CSV** (з версії 2.11) — окремий, спрощений формат: лише вогнегасники
(управління/будівля/поверх/кабінет + тип/модель/ємність/заводський/
інвентарний номер), без технічних колонок ("Тип рядка", "Ідентифікатор"),
без територій/щитів і без порожніх заглушок. Для читання (напр. в Excel),
**не для імпорту назад** — на відміну від звичайного CSV-експорту, який є
повним бекапом.

**Експорт PDF** — друкована версія обраних (чекбоксами) таблиць поточного
рівня, з контекстним заголовком (скільки управлінь/будівель/поверхів/
кабінетів з ПК/територій потрапило у звіт) для офіційної звітності.

**Готові збірки:** `builds/android/` (APK + `ВСТАНОВЛЕННЯ.md` — проста
інструкція без розробницького жаргону); `builds/iphone/` — статус iOS-версії
(без підпису Apple Developer встановлення на пристрій без Mac обмежене,
деталі в `ІНСТРУКЦІЯ.md`).
